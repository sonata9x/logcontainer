# 기능 버그 교정 — 2026-09-17

작업 브랜치: `fix/functional-bugs-september`

## 수정 범위

1. Roll20 사용자 CSS: 블록용 서비스 래퍼가 absolute 위치의 기준점을 본문 아래로 밀고 있었다. full-width content-flow를 기준점으로 사용하고 block 래퍼는 static으로 변경했다. 원본 top/bottom/padding/CSS 문자열은 수정하지 않는다. 명시적 br도 세로 레이아웃으로 보존한다. 일반 대화, 색상, 이미지 크기, 수평 중앙정렬 규칙은 유지한다.
2. 사이드바: 시작 임계값 4→8px, 폴더 내부 영역 20~80%→30~70%, 일반 행 중앙에 삽입 판단 완충 영역을 추가했다. 자동 스크롤 속도/빈도를 제한했다. 실시간 재배치로 드래그 중인 행이 커서 아래에 나타나도 마지막 삽입 의도를 취소하지 않는다. 공유 폴더 이동 선택과 개인 배치/공동 hierarchy 모델은 변경하지 않는다.
3. 핸드아웃: 제목 18px, 제목/본문과 본문/이미지 간격 28px, 본문 줄간격 1.85.
4. 핸드아웃 팝업: 보기 헤더에 수정/삭제/닫기 아이콘을 한 줄로 배치했다. 닫기의 absolute 배치를 제거하고 접근성 이름과 툴팁을 제공한다. 게시 화면은 닫기만 표시한다.
5. 빈 페이지: 최초 내용 블록 등록 UI를 추가하고 기존 수동 블록 생성 API를 재사용한다. 페이지 꾸미기/세션 카드 저장은 pages 직접 UPDATE 대신 허용된 다섯 필드만 변경하는 권한 검증 RPC를 사용한다. 삭제/교체 시 DB 변경 성공 후에만 기존 카드 파일을 제거한다.
6. YouTube BGM: INSERT RETURNING에서 새 행의 owner를 직접 검사하도록 SELECT 정책을 보강했다. stable 함수의 테이블 조회에만 의존하지 않는다. 비동기 이후 사라지는 event.currentTarget 대신 form을 보관하고 오류/성공 모두 pending을 해제한다.
7. MP3 준비: 동일한 BGM SELECT 정책을 적용한다. 두 업로드 UI에서 25MB 이하 MP3를 사전 검사한다. GPT 사이드탭의 `prompt()` 미지원도 발견하여 MP3 제목 입력을 공통 페이지 내 dialog로 교체했다. 실패 안내도 dialog 안에 표시하며 재시도할 수 있다.

## 검증

- 자동 테스트 157개 통과.
- ESLint 통과, production build 및 TypeScript 통과.
- 운영 도밍시 1부에서 문제 패턴의 스타일과 경계 좌표를 읽기 전용으로 확인했다.
- 개인 로그 대신 동일한 CSS/공백 패턴을 익명 예제로 재현한 로컬 브라우저 비교: 이전 위치 기준에서는 본문 글자가 상단 제목 영역과 11.45px 겹쳤고, 수정 후 10.23px 간격이 생겼다. CSS top/padding 수치는 동일하다.
- 전체 개인 로그를 fixture로 복사하거나 커밋하지 않았다.
- 실제 도밍시 전체의 visual parity를 완료한 것은 아니다. 원본 HTML이 로컬에 없어 전체 원본과의 픽셀 비교는 남아 있다. 모든 사용자 CSS의 absolute-only/negative-offset 조합을 임의로 보정하지 않는다.

- `[검증] 기능 수정 0917` 페이지를 생성하여 최초 수동 내용 블록과 사용자 CSS를 등록했다. 페이지 개요와 고운 돋움 폰트를 저장하고 새로고침 유지까지 확인했다.
- YouTube BGM을 등록하고 테스트 페이지에 연결했다. 새로고침 후에도 연결이 유지됐다. 재생/외부 영상 이용 가능 여부까지 검증한 것은 아니다.
- 테스트 핸드아웃의 제목/본문 간격과 수정·삭제·닫기 아이콘의 분리 배치를 실제 화면에서 확인했다.
- 테스트 페이지를 테스트 폴더 안으로 드래그한 뒤 밖으로 이동했다. 새로고침 후 루트 배치(padding-left 9px)를 확인했다. 공유 폴더 권한 선택 및 모든 순서 변경 조합을 실제 계정으로 재검증한 것은 아니다. 조작감은 사용자 재평가가 필요하다.

- 테스트 페이지, 기본 이름 `새 폴더`, 테스트 핸드아웃, 테스트 YouTube BGM은 검증 기록으로 남겨 두었다. 기존 개인 로그의 내용은 변경하지 않았다.

## 남은 검증 및 발견 사항

MP3와 세션 카드 실제 업로드는 더미 파일 저장에 대한 사용자 승인을 기다리고 있다. 승인 전 업로드하지 않았다. 권한 없는 사용자 및 공유 editor 계정의 DB 통합 테스트도 미완료다. 로컬 Supabase 환경변수가 없으므로 정적 회귀 테스트를 DB 통합 테스트로 간주하지 않는다.

GPT 사이드탭에서 기존 폴더 이름 변경의 `prompt()` 역시 지원되지 않는 오류를 발견했다. 이번 추가 수정은 MP3 업로드 입력창만 대상으로 하며, 폴더 이름 변경 및 기타 기본 prompt 기반 기능은 별도 개선 대상이다.

main 병합은 남은 업로드 검증 후 진행한다. 핸드아웃의 모든 모바일 화면 크기 및 원본 전체 visual parity를 완료했다고 주장하지 않는다.
