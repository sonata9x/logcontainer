# Architecture

## 제품 경계

이 앱은 공개 홈페이지나 게시판 목록을 제공하지 않는다.

- 인증 영역: 워크스페이스 멤버가 로그를 생성, 백업, 편집, 게시한다.
- 공개 영역: `/p/:token`에서 토큰에 연결된 로그 한 개만 읽는다.
- 공개 요청에는 워크스페이스 ID, 페이지 트리, 멤버, 다른 로그 목록을 전달하지 않는다.

## 기존 프로젝트와의 관계

- `trpghome`: Next.js/Supabase 운영 경험과 Roll20 렌더링 동작을 참고한다.
- `logedit`: 원본 HTML 보존, 블록 편집, 교정·내보내기 동작을 단계적으로 이식한다.
- `lninnawari`: RA0 로그 표현 호환성을 검증하는 기준으로 사용한다.

기존 프로젝트 파일을 새 앱에서 직접 import하지 않는다. 필요한 동작은 새 앱의 데이터 모델과 보안 경계에 맞춰 다시 구현한다.

## 핵심 보안 경계

1. 인증 영역은 Supabase Auth와 RLS로 보호한다.
2. 공개 테이블에는 anon SELECT 정책을 만들지 않는다.
3. 공개 라우트의 서버 코드만 service role로 게시 토큰을 검증한다.
4. 게시 중단 및 재게시 시 토큰을 폐기하고 새 토큰을 발급한다.
5. 로그 HTML은 허용 태그·속성·CSS만 남긴 뒤 렌더링한다.
6. 공개 페이지는 `noindex, nofollow`로 설정한다.
7. 로그인 아이디는 `profiles.username`에 보관하고 실제 이메일은 수집하지 않는다.
8. 사용자가 입력한 4자 이상 비밀번호는 서버에서 SHA-256 파생값으로 확장한 뒤 Supabase Auth에 전달한다.
9. 공개 링크 토큰은 URL-safe 12자 난수(72비트)를 사용하고 재게시할 때마다 교체한다.

## Roll20 가져오기 정리 규칙

- 현재 가져오기는 Roll20 `msgdata` 백업과 `.message` 요소가 있는 Roll20 HTML만 받는다.
- hidden message 삭제와 중복 message 삭제는 사용자가 선택한 경우에만 실행한다.
- 중복은 본문 유사도가 아니라 `data-messageid` 또는 msgdata의 `messageId`/객체 키가 정확히 같은 경우만 판정한다.
- 같은 ID는 정렬된 원본 순서에서 첫 항목을 남긴다.
- ID가 없는 메시지는 내용이 같아도 삭제하지 않는다.
- 삭제 전 전체 HTML은 `logs.original_html`에 그대로 보관한다.

2. 핸드아웃/이미지의 비공개 Storage 백업과 프록시
3. 중첩 페이지 트리의 드래그 정렬
4. TXT 교정 미리보기와 다운로드
